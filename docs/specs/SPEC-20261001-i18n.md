## 1. User Story

**As a** usuário do Open WebUI
**I want** escolher o idioma da interface
**So that** a UI suporte múltiplos idiomas como no upstream (i18n completo).

**Problem context:**
UI com strings pt-BR hardcoded em todos os `.razor` (`docs/MIGRACAO-DOTNET.md:71` — ⬜). Sem arquivos de recurso nem seletor de idioma.

## 2. Scope

**In scope:**
- Mecanismo de i18n no cliente Blazor: arquivos JSON de locale (`wwwroot/i18n/{lang}.json`) + serviço `ILocalizationService` com interpolação.
- Extração das strings atuais para `pt-BR` como locale base + `en-US` traduzido.
- Seletor de idioma em Settings (persistido em `localStorage`, aplicado pre-paint como o tema).
- `[A DEFINIR]` conjunto inicial de idiomas — recomendado: `pt-BR` + `en-US` (upstream tem dezenas via community translations).

**Out of scope:**
- Tradução de conteúdo do backend (mensagens de erro de API ficam em inglês/padrão).
- RTL completo (upstream tem bugs conhecidos — fora do escopo inicial).
- Crowdin/gerenciamento de traduções da comunidade.

## 4. Requirements

### RF-001: Serviço de localização
- **Description:** `LocalizationService` carrega locale JSON, resolve chaves com fallback para `pt-BR` e notifica componentes na troca.
- **Rules:** chave ausente → mostra a chave (modo debug) ou fallback; troca de idioma sem reload.
- **Input → Output:** `key + lang` → string localizada

### RF-002: Extração das strings
- **Description:** Todas as strings de UI visíveis extraídas para `pt-BR.json` e traduzidas em `en-US.json`.
- **Rules:** placeholders `{{param}}` para interpolação; nada de string solta nova sem chave.

### RF-003: Seletor e persistência
- **Description:** Dropdown de idioma em Settings; `localStorage webui.locale`; aplicado no boot.
- **Rules:** default `pt-BR`; inválido → fallback.
