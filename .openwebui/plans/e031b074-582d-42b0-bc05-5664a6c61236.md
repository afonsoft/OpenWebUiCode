## 1. User Story
As a desenvolvedor e usuário do Open WebUI Code,
I want incorporar as melhores práticas, arquiteturas de orquestração multi-agente (como o épico "Batuta" do alltomatos/opencode) e recursos avançados do OpenCode v2 (agentes declarativos em Markdown, CLI config, orquestração de workers em git worktrees, diffs estruturados e detecção de ociosidade em PTY),
So that nosso ambiente de coding agent em .NET ofereça capacidade robusta de engenharia autônoma, orquestração paralela segura, flexibilidade de configuração por camadas e paridade de ponta com os melhores harnesses de agentes do mercado.

## 2. Scope
### In Scope
- **Arquitetura de Orquestração Multi-Agente (Estilo Batuta):**
  - Papéis estruturados: *Arquiteto* (análise de repo, PRD e planejamento em `docs/batuta-pipeline.md`), *Orquestrador* (distribuição de issues, delegação e revisão estrita de diff antes de mergear) e *Workers* (sub-agents isolados ou CLIs externos em PTY).
  - Isolamento estrito por Git Worktree por worker (`workspaces/{user}/worktrees/{owner}__{repo}/{chatId}` e branch `chat/{chatId}`), garantindo concorrência sem colisões.
  - Status vivo em arquivo Markdown partilhado (`.batuta/{activityId}/pipeline.md` ou equivalente persistido no banco e espelhado no workspace).
  - Detecção de término de turno de ferramentas externas em PTY baseada em silêncio de saída (`idle` timeout configurável).
- **Agentes Declarativos (.agent.md):**
  - Descoberta e parsing de arquivos `.agent.md` (com frontmatter YAML contendo `system`, `model`, `mode`, `permissions`, `steps`, `hidden`, `color`) nas pastas `.claude/agents/`, `.agents/` e diretório raiz do workspace.
  - Integração com o seletor de agentes e ferramentas de delegação (`delegate_task`).
- **Configuração Global / Avançada (Estilo CLI config do OpenCode v2):**
  - Camada de configuração unificada para temas, comportamento de diffs (unified/split, wrap, tree), preferências de sessão e políticas de permissão.
- **Melhorias de Diffs, Contexto e Reunião de Resultados:**
  - Visualização de diffs estruturados na aba Changes do Workspace.
  - Mecanismos de recontagem de tokens, compactação seletiva (`ChainCompactor` / resumos) e recuperação via `history://`.

### Out of Scope
- Alterações no gateway core original do Open WebUI (FastAPI/Svelte upstream), mantendo a arquitetura .NET 10 / Blazor como fonte de verdade.
- Modificações em pipelines de CI oficiais (`.github/workflows/`) sem revisão humana explícita.
- Execução arbitrária de código sem checagem de camadas de aprovação e risk tiers (T1/T2/T3).

## 4. Requirements

### RF-001: Descoberta e Execução de Agentes Declarativos (.agent.md)
- **Description:** O sistema deve escanear e carregar definições de agentes declarativos a partir de arquivos `.agent.md` encontrados no workspace e diretórios globais (`~/.agents`, `.claude/agents/`).
- **Rules:**
  - O frontmatter YAML deve ser validado para extrair `name`, `system`, `model`, `mode`, `permissions` e `steps`.
  - Agentes declarativos devem poder ser invocados diretamente via `delegate_task` com o parâmetro `agent: "nome"`.
- **Input → Output:**
  - Input: Arquivo `.agent.md` com metadados e prompt de sistema.
  - Output: Registro do agente no catálogo de runtime disponível para o Orquestrador.

### RF-002: Pipeline de Orquestração Multi-Agente (Modelo Batuta)
- **Description:** Suporte a um fluxo em três camadas (Arquiteto → Orquestrador → Workers) com persistência de progresso em arquivo de pipeline Markdown.
- **Rules:**
  - O Arquiteto gera o documento de planejamento inicial (`docs/batuta-pipeline.md`).
  - O Orquestrador despacha tarefas para workers isolados em worktrees dedicados.
  - Nenhuma alteração é mesclada ao branch principal sem revisão prévia de diff pelo orquestrador/usuário (`worktree_merge`).
- **Input → Output:**
  - Input: Requisito de alto nível do usuário.
  - Output: Pipeline executado com checkpoints atômicos por worker e relatório de diff revisado.

### RF-003: Detecção de Ociosidade em PTY para Sub-Agentes Externos
- **Description:** Monitoramento de sessões PTY de CLIs externos (como Claude Code ou Codex) baseado em silêncio de saída.
- **Rules:**
  - Se a saída do PTY permanecer inativa por um limiar configurável (ex: 1.5s a 5s) e o processo estiver aguardando input, o turno é considerado concluído.
  - Proteção contra loops infinitos com timeout máximo (ex: 5 minutos).
- **Input → Output:**
  - Input: Fluxo de bytes da saída PTY do processo filho.
  - Output: Sinal de conclusão de turno para o agente supervisor.

### RF-004: Configuração Global Unificada (Estilo CLI Config)
- **Description:** Interface de configuração centralizada para preferências de interface, temas, políticas de diff e comportamentos de sessão.
- **Rules:**
  - Resolução hierárquica: Global → Admin → Usuário → Projeto.
- **Input → Output:**
  - Input: Objeto de configuração atualizado via API/UI.
  - Output: Persistência e aplicação imediata nos serviços dependentes.

## 5. API Contract
- `POST /api/v1/agents/declarative/reload`: Recarrega o catálogo de agentes declarativos `.agent.md`.
- `GET /api/v1/batuta/pipelines/{id}`: Retorna o status atual do pipeline de orquestração Batuta.
- `POST /api/v1/batuta/pipelines/{id}/dispatch`: Despacha uma issue para um worker isolado em git worktree.
- `POST /api/v1/batuta/pipelines/{id}/review`: Submete a revisão de diff antes do merge.

## 6. Acceptance Criteria
### Cenários BDD
- **Given** um repositório com um arquivo `.agent.md` personalizado na pasta `.claude/agents/`,
- **When** o usuário solicita uma tarefa delegando para esse agente (`delegate_task`),
- **Then** o sistema lê o frontmatter e o prompt do arquivo, inicializa o sub-agente com a configuração especificada e isola a execução no worktree do chat.

- **Given** um pipeline Batuta ativo com múltiplas issues,
- **When** o orquestrador despacha uma issue para um worker,
- **Then** um git worktree exclusivo é criado, a tarefa é executada, e o diff gerado fica disponível para revisão antes de qualquer operação de merge.

### Edge Cases
| Scenario | Input | Expected behavior |
|---|---|---|
| Arquivo `.agent.md` malformado | Frontmatter YAML inválido | Log de erro amigável, ignorar o arquivo sem quebrar o boot do sistema |
| Conflito de worktree | Tentativa de criar worktree em path já existente | Limpeza automática do worktree órfão e recriação limpa |
| Timeout de PTY externo | Processo externo trava ou demora mais que 5 min | Interrupção controlada do processo com notificação de timeout |
